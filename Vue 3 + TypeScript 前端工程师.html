阶段 1：Web 基础 + 现代 JavaScript（第 2~4 周）★

CSS 文档流：移动端开发者最大的思维转变

  • 原生布局是"我指定你放在哪"；CSS 默认是文档流——块级元素独占一行堆叠、行内从左到右、放不下自动换行
  • 脱离文档流只有三种方式：float（历史产物）、position: absolute/fixed、flex/grid 子项
  • 项目入口必写 * { box-sizing: border-box; }——width 即最终占宽，一刀切解决 padding 撑破问题
L3：移动端关键 meta 与 DPR
<meta name="viewport" content="width=device-width,
  initial-scale=1.0, viewport-fit=cover">
/* 物理像素 = CSS 像素 × devicePixelRatio
   与 dp/sp 的换算逻辑本质相同 */

图片优化：srcset 多分辨率、loading="lazy"、<picture> 艺术指导。安全区：padding-bottom: calc(12px + env(safe-area-inset-bottom))。

Flexbox：90% 场景的布局方案

  • justify-content 管主轴、align-items 管交叉轴、gap 替代 margin 塌陷
  • flex: 1（1 1 0%）= 严格等分剩余空间；flex: auto = 按内容比例分配
  • 左侧固定 + 右侧自适应时，右栏加 min-width: 0 防 flex 子项默认 min-width:auto 撑破
L3：移动端三段式布局（每天在写）
/* 头部固定 + 内容滚动 + 底部固定 */
.page { display: flex; flex-direction: column; height: 100vh; }
.page header { flex: none; }
.page main   { flex: 1; overflow-y: auto; }
.page footer { flex: none; }
/* 水平垂直居中 */
.center { display: flex; justify-content: center; align-items: center; }

Grid：二维布局与零媒体查询的响应式卡片

  • grid-template-areas 命名区域，仪表盘骨架可读性极佳
  • 必背一行：repeat(auto-fill, minmax(240px, 1fr))——视口变窄自动 4→3→2→1 列，零媒体查询
  • 选型口诀：内容决定尺寸（按钮条）→ Flex；先划分结构（页面骨架）→ Grid

BFC 与层叠上下文：两个"玄学 bug"的元凶

  • BFC 触发：overflow 非 visible、flex/grid、absolute 等；解决 margin 塌陷、高度塌陷、两栏环绕
  • z-index 只在同一层叠上下文内比较——transform / opacity<1 的父级会创建"小世界"
  • 弹窗 z-index:999 仍被盖住？Vue 3 的 <Teleport to="body"> 专治此症（见 05 节）
L3：position 五值速查

static 默认 ｜ relative 相对自身偏移、常作锚点 ｜ absolute 相对最近非 static 祖先 ｜ fixed 相对视口（吸底栏）｜ sticky 滚动阈值后固定（表头吸顶）。

闭包：函数 + 词法作用域的组合

  • 内层函数引用外层变量，外层执行结束后变量不会被回收
  • 四大应用：私有变量、函数工厂、防抖节流的实现基础、Vue Composable "记住状态"的底层机制
  • 两个坑：循环 + var（let 每轮新建块级作用域）；意外持有大对象 → 内存泄漏——这正是 onUnmounted 必须清理监听的原因
L3：最小示例
function createCounter() {
  let count = 0              // 私有变量
  return function () { return ++count }
}
const counter = createCounter()
counter() // 1 —— createCounter 早已执行完，count 却活着
counter() // 2

this 指向：四规则 + 箭头函数

  • 优先级：new > 显式（call/apply/bind）> 隐式（谁调用指向谁）> 默认（window/undefined）
  • 高频坑：const fn = obj.say; fn()——赋值后调用者丢失
  • 箭头函数没有自己的 this，取定义时外层的词法 this（等价 Kotlin Lambda）
  • Vue 3 <script setup> 中 this 被刻意禁用——this 问题主要出现在读旧代码时

原型链与 class：心智直接套用 Kotlin/Java

  • 对象经 __proto__ 链条查找属性，终点 Object.prototype.__proto__ === null
  • class 是原型机制的语法糖；#field 是真私有字段
  • 子类 constructor 必须先 super()——等价先初始化父类构造

ESM：Vite 一切魔法的基石

  • ESM 是静态结构（导入导出编译期确定）——Tree Shaking 的前提、Vite 按需编译快的根源
  • CommonJS（require）是运行时动态加载，看懂即可
  • 每个文件最多一个默认导出；import * as utils 命名空间导入

数组高阶方法：前端的"集合流操作"

  • map/filter/concat/slice 返回新数组；sort/splice/reverse/push 是原地修改——会直接改变响应式数据
  • reduce 第二参数（初始值）必传；sort 数字排序必须传比较函数（默认按字符串排，高频坑）
  • 数组去重一行：[...new Set(arr)]

Promise：三态不可逆，then 链会"传递"

  • pending → fulfilled / rejected，一旦落定不可逆
  • then 中 return 另一个 Promise → 链条等待它落定（串行的原理）；throw → 被最近 catch 捕获
L3：并发四兄弟（面试必考）

all 一损俱损（多独立请求齐渲染）｜ allSettled 全要结果（批量上传知成败）｜ race 先到先得含失败（超时控制）｜ any 第一个成功的（多 CDN 竞速）。

async/await：无依赖的请求必须并行

  • await ≈ Kotlin suspend ≈ Swift async/await；挂起期间事件循环继续转
  • 串行 await a; await b 耗时相加；Promise.all([a, b]) 同时发、一起等
  • await 的 rejection 可被 try/catch 捕获，需要继续抛出让调用方感知

事件循环：前端面试第一原理题

  1. 执行同步代码调用栈逐行执行，栈未清空一切排队
  2. 异步 API 交接定时器/网络回调交给 Web API 线程，就绪后入队
  3. 栈清空 → 清空全部微任务Promise.then / await 后续 / queueMicrotask，优先级最高
  4. 取一个宏任务setTimeout / I/O / UI 事件回调——注意 0ms 也不是立刻
  5. （必要时渲染）→ 下一轮循环长任务会阻塞渲染掉帧，切片丢进宏任务缓解
L3：经典输出题（必须能秒答）
console.log('1')                              // 同步
setTimeout(() => console.log('2'), 0)         // 宏任务
Promise.resolve().then(() => console.log('3'))// 微任务
console.log('4')                              // 同步
// 输出：1 → 4 → 3 → 2
// await 后面的代码 = .then 回调 = 微任务

实战意义：① Vue.nextTick 就是用微任务实现的；② 长任务拆片用宏任务或 requestIdleCallback。

事件委托：列表上千项的性能关键

  • 利用冒泡把 N 个子元素监听挂到父元素；e.target.closest('li') 定位实际目标
  • Vue 对应：@click.stop / @submit.prevent / @keyup.enter 修饰符直接写在模板

Map / Set / WeakMap：为读 Vue 源码铺路

  • Map vs 对象：任意类型做键、有序、频繁增删性能更好
  • WeakMap：Vue 响应式内部用它存"对象→依赖"，防止框架持有的映射阻止对象回收

阶段 1 自查：手写防抖与节流（默写级）

展开参考实现
// 防抖：停止触发 delay 后才执行（只要还在动就不执行）→ 搜索联想、resize
function debounce(fn, delay = 300) {
  let timer = null
  return function (...args) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}
// 节流：固定间隔内最多一次（再频繁也按时执行）→ 滚动加载、按钮防连点
function throttle(fn, interval = 300) {
  let last = 0
  return function (...args) {
    const now = Date.now()
    if (now - last >= interval) { last = now; fn.apply(this, args) }
  }
}

阶段 2：TypeScript 系统学习（第 5~7 周）

总认知：TS = JS + 编译期类型系统，运行时全部擦除

  • 默认 const、能推断就不手写、永远不用 any
  • 联合类型是 TS 表达"多态"的日常手段：'idle' | 'loading' | 'success' | 'error'

interface 支持声明合并；type 能表达联合/交叉/条件/映射

  • 同名 interface 自动合并（给第三方库扩展留口子）；type 不行
  • 交叉 A & B 是机械合并；interface extends 会检查兼容性
  • 社区惯例：对象结构优先 interface，联合/工具类型/映射用 type

any 放弃检查；unknown 用前必收窄；never 用于穷尽性检查

  • any：双向兼容一切，编译器躺平——禁用
  • unknown：任何值可赋给它（单向），使用前必须收窄——处理接口响应、JSON.parse 的正解
  • never：不可能存在的类型；switch 的 default 接住它，未来漏处理新分支时编译期直接报错

判别式联合：前端"状态建模"的标准范式

  • 多个类型共享一个字面量"标签"字段；检查标签 → TS 自动收窄到对应分支
  • success 状态才有 data、error 状态才有 message——杜绝大杂烩类型的"哪个字段该有"困惑
L3：RequestState 建模
type RequestState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: User[] }
  | { status: 'error'; message: string }
function render(s: RequestState) {
  switch (s.status) {
    case 'success': return s.data.map(u => u.name) // ✔ 有类型
    case 'error':   return s.message               // ✔ 有类型
    default: { const _: never = s; return _ }      // 穷尽性检查
  }
}

泛型 + keyof：类型安全的属性访问

  • 泛型约束 T extends { length: number } 限定 T 的能力
  • prop(obj, key) 模式：传错属性名编译期直接报错——Vue 源码/工具库大量使用
  • interface ApiResponse<T = unknown> 默认类型参数

工具类型：DTO 建模的七把瑞士军刀

  • Partial 更新接口 ｜ Pick 列表瘦身 ｜ Omit 创建接口去掉后端生成的 id
  • Record<K,V> 字典/枚举翻译 ｜ ReturnType 提取函数返回类型 ｜ Awaited 提取 Promise 值类型
L3：手写映射类型（面试高频）
type MyPartial<T>   = { [K in keyof T]?: T[K] }
type MyPick<T, K extends keyof T> = { [P in K]: T[P] }
type MyReturnType<T> =
  T extends (...args: any[]) => infer R ? R : never
// infer：在条件类型中"声明一个待推断的变量"

断言、satisfies 与类型守卫

  • as 是逃生舱不是常规手段；双重断言 unknown as T 是最后手段
  • satisfies（TS 4.9+）：校验类型但保留更精确的字面量推断——现代推荐
  • 自定义守卫 function isUser(v: unknown): v is User，通过后自动按 User 处理

tsconfig 关键项

  • "strict": true——严格模式全家桶，企业项目必开
  • "noUncheckedIndexedAccess": true——arr[i] 自动带 undefined，防越界
  • paths: { "@/*": ["src/*"] } 与 Vite alias 同步

阶段 3：Vue 3 核心技术（第 8~12 周）· 主战场

响应式 = Proxy 代理 + 依赖收集 + 派发更新

  • 组件渲染函数被包在一个 effect 里：模板读数据 → Proxy get → track 记录依赖；改数据 → set → trigger → 重跑 effect
  • Proxy 三大优势：监听属性增删、监听数组索引/length、惰性深层代理（访问到才递归）
  • 依赖存于 WeakMap<target, Map<key, Set<effect>>>，自动收集、无需手动声明
L3：为什么 ref 需要 .value

基本类型无法被 Proxy 代理——Vue 把它装进带 value 属性的"盒子对象"再代理盒子；.value 的 get/set 就是依赖收集/派发的触发点。模板中编译器自动插入 .value，所以不用写。

默认全用 ref，reactive 只留给表单聚合

  • 坑 1：reactive 解构丢失响应性——值被"拷出" Proxy；解法 toRefs(state)
  • 坑 2：整体替换丢失响应性——解法 Object.assign(state, newData)
  • 大列表用 shallowRef（只监听 .value 整体替换）+ triggerRef() 手动触发
统一心智：ref + .value 可避免 reactive 的全部三大坑。

computed：有缓存的派生值，不应有副作用

  • 依赖不变直接返回缓存；不要在里面发请求/改其他状态
  • 可写 computed 充当双向绑定中间层（get/set）——如 TodoMVC 的"全选"
  • 缓存原理：带 dirty 标记的惰性 effect——依赖变化只置 dirty，下次读取才重算

watch：明确指定"监听谁"，懒执行，能拿新旧值

  • 监听 reactive 单属性用 getter：watch(() => user.age, cb)
  • immediate 初始化立即执行；flush: 'post' 拿更新后 DOM
  • 监听同一路由组件参数变化：watch(() => route.params.id, fetchData)——组件被复用不会重建

watchEffect：立即执行，读到谁就自动监听谁

  • 适合"副作用与依赖一目了然、不关心旧值"：如自动同步 localStorage
  • onCleanup 清理副作用——用 AbortController 取消上一次请求，防竞态（旧响应覆盖新数据）
口诀：算出来的值用 computed；要旧值/明确目标用 watch；自动追踪副作用用 watchEffect。

模板语法四条铁律

  • v-if 真创建/销毁（条件少变：权限、错误页）；v-show 仅 display 切换（频繁切换：Tab、hover）
  • v-for 的 key 必须是稳定唯一 id，禁止 index——见 07 节 diff 原理
  • v-for 与 v-if 不同标签：用 computed 先过滤
  • v-html 渲染富文本有 XSS 风险，内容必须可信或消毒

生命周期：onUnmounted 是线上事故防线

  • onMounted：请求数据、初始化图表、addEventListener
  • onUnmounted 必须清理：clearInterval、removeEventListener、AbortController.abort()——不清理 = 内存泄漏 + 幽灵回调
  • KeepAlive 缓存页的数据刷新放 onActivated（每次进入触发），不放 onMounted（只执行一次）

defineModel：一行搞定组件双向绑定

  • Vue 3.4+：const model = defineModel<string>({ required: true })——编译为 :modelValue + @update:modelValue
  • 支持多个 v-model（defineModel<string>('title')）与修饰符处理
  • 单向数据流原则：子组件禁止直接改 props，需要"改"就 emit 或用 v-model 模式

  • 用 InjectionKey<Ref<Theme>> + Symbol 做类型安全 key
  • provide 时包 readonly()——防后代篡改，单向数据流贯彻到底

  • 定时器类（useCountDown）必须在内部 onUnmounted 清理

nextTick：DOM 异步批量更新的产物

阶段 5：原理、性能与浏览器网络（第 17~22 周）★ 中高级门票

手写迷你响应式：50 行讲清 track / trigger

  • 存储结构：WeakMap<target, Map<key, Set<effectFn>>>；get 时 track、set 值真变了才 trigger
  • effect 先 cleanup 旧依赖再执行——处理"条件分支导致依赖变化"
  • Vue 真实调度是批量异步：trigger 不直接执行 effect，入队微任务去重后统一跑——这就是 nextTick 存在的原因
L3：effect 与 computed/watch 的关系

effect(fn) 就是组件渲染的包装（render 函数即 effect）；computed 是带 dirty 缓存、不立即执行的特化 effect；watch 是"指定源 + 用户回调"的 effect。

diff 与 key：为什么禁止用 index

  • 四大规则：只同层比较、不同类型节点直接销毁重建、靠 key 判断"同一个节点"、静态内容跳过
  • index 作 key 头部插入时：旧 A(key=0) 配对新 X(key=0)——全量就地更新内容 + 表单组件状态错乱（输入框内容残留）
  • Vue 3 编译优化：PatchFlag（只 diff 动态部分）、Block Tree（拍平收集动态节点）、最长递增子序列（最小化 DOM 移动）

从输入 URL 到页面展示（标准答题版）

  1. URL 解析 → DNS 解析逐级缓存：浏览器→系统→路由器→运营商→递归查询
  2. TCP 三次握手 → TLS 握手HTTPS 场景额外协商密钥
  3. 发送 HTTP 请求 → 服务器返回 HTML
  4. 解析 HTML 建 DOM 树同步 <script> 阻塞解析：defer 保序在 DOMContentLoaded 前执行；async 下完即执行不保序
  5. CSSOM → Render Tree → Layout → Paint → CompositeRender Tree 不含 display:none 节点；Composite 走 GPU 分层

重排 / 重绘 / 合成：动画只用 transform 与 opacity

  • 重排：几何变化，Layout→Paint→Composite 全跑，代价大；重绘：仅外观
  • 合成：仅 transform / opacity，GPU 合成层处理，动画首选
  • 避免强制同步布局：读 offsetTop 后紧跟写样式会迫使同步重排——先集中读、后集中写

跨域：限制的是"读取响应"，不是"发不出去"

  • 同源策略下，简单请求直接发送带 Origin 头；服务端回 Access-Control-Allow-Origin 即可读
  • 预检请求触发条件：PUT/DELETE/PATCH、Content-Type 为 JSON、自定义头（Authorization）——你的 Axios 封装每次跨域都伴随一次 OPTIONS
  • 带 Cookie：withCredentials: true + 后端 Allow-Credentials 且 Origin 不能是 *
  • 开发期 Vite proxy；生产期 Nginx 反向代理同域部署——一劳永逸

HTTP 缓存：强缓存 → 协商缓存两级瀑布

  • 强缓存 Cache-Control: max-age 未过期直接用本地，不发请求
  • 过期后协商：ETag（If-None-Match）优先于 Last-Modified；资源没变回 304（无 body）
  • 实战：hash 资源 max-age=31536000, immutable；index.html no-cache——"发布后用户看到旧版本"九成是这里配错

认证：JWT 双 Token 是企业主流

  • Session 状态在服务端 + Cookie 自动携带（App 原生请求没有这层自动机制）
  • JWT 存 localStorage（XSS 可窃）vs HttpOnly Cookie（防 XSS 但需防 CSRF）
  • 主流实践：access token 短期 + refresh token 长期 + 401 无感刷新；CSRF 用 Token / SameSite 防御

跨端与全栈延伸（选修）

  • Nuxt 4：SSR 首屏快 + SEO；理解 SPA / SSR / SSG 取舍即可
  • uni-app / Taro：原生背景 + H5 = 混合开发赛道的差异化竞争力，转型过渡期的黄金岗位选择
  • Node.js：Koa/Express + JWT 中间件打通全栈认知闭环，不必深入

综合面试问答精选（中高级标准）

六道高频题的标准答案

Q1：Vue 3 响应式原理，从数据修改到视图更新的完整链路？

① 渲染函数被包装为 ReactiveEffect 运行；② 模板读数据触发 Proxy get → track 记入依赖集合（targetMap: WeakMap<target, Map<key, Set<effect>>>）；③ 修改触发 set，值变化时 trigger；④ effect 入队，微任务中去重后批量执行；⑤ 生成新虚拟 DOM，经 Patch Flag 优化的 diff 得最小变更集应用到真实 DOM。

Q2：Vue 2 与 Vue 3 响应式差异？

Vue2 用 defineProperty：初始化递归遍历整棵树（大对象慢）、无法监听属性增删（需 $set）与数组索引（重写七个方法）；Vue3 用 Proxy：拦截一切读写、惰性深层代理、数组与增删天然支持，WeakMap 存依赖防泄漏。局限：Proxy 无法代理基本类型——所以有 ref。

Q3：computed 缓存原理？

computed 是带 dirty 标记的惰性 effect：首次读取才求值；依赖变化只置 dirty 并通知读取过它的 effect，不立即重算；下次读取发现 dirty 才重算并更新缓存——"依赖不变时多次读取零开销"。

Q4：跨域是什么？你们项目怎么解决的？

同源策略限制 JS 读取非同源响应。标准方案 CORS（区分简单请求 / 预检 OPTIONS，带 Cookie 需 withCredentials + 精确 Allow-Origin）；开发期 Vite proxy；生产期 Nginx 反向代理同域部署（我们项目的做法，一劳永逸）；历史方案 JSONP 仅 GET。

Q5：强缓存与协商缓存？项目中如何配置？

hash 资源 max-age=31536000, immutable 永久强缓存（内容变则文件名变）；index.html no-cache 每次协商——保证入口最新，从而加载新 hash 资源，解决"发版后旧版本"问题。

Q6：手写题清单（全部默写级）
